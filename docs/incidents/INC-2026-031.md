# INC-2026-031: Lost pending proof of delivery

**Date:** 2026-08-21

**Status:** Interim mitigation shipped in 5.2.1; durable recovery outstanding

## Summary

Driver app termination during a stop could discard pending POD captures before
Dispatch acknowledged the upload. This reference incident uses no customer data.

## Interim mitigation

POD photos now go through AES-256 encrypted `SecureStorage` in the app sandbox.
The `pendingCaptures` array still holds signature bytes and photo references in
memory until an upload succeeds. Process termination can therefore lose the
signature and orphan the encrypted photo. A failed foreground upload retains
the current in-memory capture so a driver can explicitly retry.

## Follow-up

[ADR-014](../adr/ADR-014-offline-first-sync.md) replaces this transient state with
encrypted SQLite and a persistent outbound event queue. MDS-3 retention and
dispatcher escalation remain separately scoped work; never delete unsynced
evidence merely because it has aged out.
